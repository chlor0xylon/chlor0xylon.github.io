This is the third part of a series on reproducing recent advancements in computer vision interpretability. In the [first part](/posts/dinov3-prototypes-part-1/), I introduced the history of feature visualization. In the [second part](/posts/dinov3-prototypes-part-2/), I learned a dictionary of concepts from DINOv3 latents. Here, I outline the procedure to generate prototype images from the learned concepts.


## Methodology & implementation details

Let's introduce the main steps throughout the process of computing prototypes as well as some implementation details.


In order to get concepts and visualize them altogether according to the approach proposed by @holistic2023fel, I wrote several Python scripts that given a Hugging Face model and a dataset, perform in turn the following steps:
- A custom `ImageNetDataset(torch.Dataset)`
    - scrapes and indexes images from the downloaded ImageNet dataset file tree structure as well as some metadata like image size and saves them in a Polars dataframe to emulate a tiny database;
    - filters images to select those whose dimensions lie above 64 pixels in both width and height (which only eliminates a negligible proportion of the dataset, see <a data-figure-ref="fig-imagenet-density"></a>);
    - generates and appends some random augmentation transform codes to the batch generated by a custom-made `TransformsMaker` factory (for example, in our case setting, transform codes model random crops to extract concepts from intermediate-sized image regions).

```python
@dataclass
class InputImageBatch:
    """Container for processor-ready model inputs and per-sample metadata."""
    images: transformers.feature_extraction_utils
    labels: torch.Tensor
    ids: torch.Tensor
    tracked_transform_codes: list[str]
```

- A conventional wrapper `ImageNetDataLoader(torch.DataLoader)` retrieves images from the dataset drawn at random and transforms them on the fly according to the transform codes.
- A processing loop streams those formed batches to the model adapter, which extracts their latent CLS token or pooled outputs and repackages the model outputs, unique ids and transform codes to be replayed later upon retrieval.
- A custom-made `ArrayArtifactStore` persists the raw batched model outputs as binary numpy format sharded them into batches on disk, and saves the metadata transform codes and ids to a Polars bookkeeping registry.
- A specialized dictionary learning script iteratively updates the dictionary weights and persists them on disk, relying on:
    - a custom new `VectorDataset(torch.Dataset)` with manually-paginated lazy loading capability via `__getitems__` to leverage OS-level file caching instead of making one (or using numpy's memory map) and decouple the requested materialization batch size in memory from the sharding size on disk;
    - yet another dataloader wrapper `VectorDataLoader(torch.DataLoader)`.
- A concept visualizer script is responsible for
    - reading the concepts saved on disk;
    - triggering a custom-made `VectorDataset` method that leverages [Usearch](https://github.com/unum-cloud/usearch) to build a compacted vector index to be able to compute efficient matching & retrieval later;
    - retrieving the closest matches in the dataset's saved latents (in terms of cosine distance) for every concept vector of the dictionary;
    - reloading images from the disk then replaying their transformations and finally displaying them.
